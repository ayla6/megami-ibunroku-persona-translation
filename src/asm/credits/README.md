# The staff roll shortcut (base game)

Select on the title screen plays the translated staff roll without starting a
game, then returns to the title. This is base-game content, not an optional
enhancement: `main.asm` includes these files in every build (translation and
`--qol`), and `build.py` does not list or gate them.

## Files

- `credits/open.asm` (OPEN.EXE): the title input handler's Select hook and the
  sentinel dispatch.
- `credits/slps.asm` (resident): the title switch's sentinel branch.
- `build/end_credits.asm` (END.EXE): generated by
  `src/injection_tools/end_credits.py`.

## How it works

The title menu's input handler tests the press against the ordinary confirm
bits (Circle or Start). Select is unused there, so the OPEN.EXE hook claims
it: Select writes `g_title_choice = 0xFE` (the sentinel) and `g_card_scan =
-1`, then returns through the menu's own choice epilogue. The press word is
the title loop's InitPAD read at `0x800826A0`; its port buffer puts
Select..Left in the third byte and the loop shifts that into the high half,
so Select is `0x0100` (the bit the title's own card path tests at
`0x80081C98`). `test_credits_hook` derives that bit from the game's pad
reader rather than pinning it by hand.

The resident title state reads `g_title_choice` and indexes retail's
five-entry switch. `credits/slps.asm` replaces only retail's bounds test
(`0x80011550`/`0x80011554`) with a jump to the dispatch in the second half of
the OPEN.EXE dead function, which is mapped while the title is live:

- a retail choice runs retail's own `sltiu v0,v1,5` there and rejoins the
  untouched lookup at `0x80011558`; an out-of-range value takes retail's
  fallthrough at `0x800113F0`. The lookup, its table and every case are
  retail's bytes;
- the sentinel starts the credits: it sets `g_movie_id = 0x35` (END.EXE
  ending 5), `g_movie_next_state = -1` (back to the boot/title state) and
  `g_state_next = GAME_STATE_MOVIE`.

Ending 5 is a six-word END.EXE script table moved into a dead function
(`0x80091818`) so it can hold one more entry, plus the credits-only script. The
script is not written by hand: `end_credits.py` takes the staff-roll tail of
retail ending 1's script. The credits text pages are the `n` (roll) rows of the
END.BIN page map, translated mechanically through `g_end_sectors`; the script
starts at the nearest kind-0 artwork load above the first roll page (so the
roll keeps its backdrop) and keeps the music opcode already before it. The
remaining halfwords are copied verbatim except the last one: retail endings 1
and 2 hold their last screen with END.EXE's no-op `0xA`, and ending 5 turns
that into the `0x9` end opcode, so `done:` returns the resident to the title
instead of freezing. The ending-script reader
(`lui at, 0x800a` / `addiu at, at, -0x600c` at `0x80080D90`) is repointed at
the six-entry table. The retail table and every retail script stay in place.

The credit pages' line pitch is 18 rows (16-row glyph cells with two rows
between) with an extra 8 rows before each job title after the first. A block
that would run past the page moves up just enough to fit; if it cannot fit at
all, `endtext.py` fails the build rather than overlapping lines. The rule is
stated with the other layout rules in `docs/TEXT_LAYOUT_SPEC.md`.
`tools/tests/test_end_credits.py` checks the generator against the retail
script and the generated assembly bytes; the QoL write-guard suite assembles
the base build (which always carries the credits script) and every QoL
variant.
